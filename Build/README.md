# 统一构建与发布

在 Windows 安装 Python 3.10+、.NET 8 SDK 和 PowerShell 7。使用配套游戏目录作为二进制及图片输入，不下载编译依赖。

```powershell
# 构建、测试、打包和复制安装演练；不安装到正式游戏
./release.ps1 -GameRoot 'D:\Games\ZM3'

# 同一条流程全部通过后，直接覆盖固定名称的当前版本
./release.ps1 -GameRoot 'D:\Games\ZM3' -Install

# 已验证产物仍完整且源码未变时，只执行安装及安装后校验
./release.ps1 -GameRoot 'D:\Games\ZM3' -Resume -Install
```

可用 `-Output` 指定工作目录。默认在源码 `bin/release-output` 内，不在正式游戏目录生成归档。所有外部命令使用参数数组传递路径，后台及测试窗口采用隐藏启动参数。

流程按顺序执行：

1. 校验配套游戏、启动器及冻结后台的 SHA256，以及旧补丁源码与已声明二进制的对应关系。任何未知变动先停止。
2. 按源码资源清单补齐缺少的图片；编译统一规则，生成数据和 C#/Python 指纹，同步历史兼容目录的后台副本。
3. 运行礼包、事务、运行状态、HTTP 缓存、规则及发布门禁测试。
4. 从源码构建 QA 修改器，执行完整界面回归，并核对 C#/Python 规则指纹。
5. 从配套冻结程序中提取原 Python 3.8 解释器和标准库，生成仅供隔离服务使用的测试端口包装；用 50 KB 的精确标签差量重建测试游戏，避免源码包重复携带整个游戏。
6. 验证真实冻结后台、真实游戏和礼包领取，以及 C#/Python 跨进程锁和双向恢复。
7. 构建正式修改器，生成资源版本清单、精简源码包和带原始文件哈希的安装计划。
8. 从发布 ZIP 解压并还原图片，在干净目录实际重新构建修改器。
9. 在复制安装目录注入安装中断，确认所有程序回滚，随后完整安装并核对资源。执行实际启动器的完整性函数及故意损坏反向检查。
10. 可选安装：核对未占用的固定修改器路径，持公共存档锁检查无待恢复事务，备份并原子替换程序。只停止并重启本目录后台，不关闭游戏窗口。检查服务目录、程序与规则版本、全部资源，以及启动器 281 项校验。存档、领取记录、设置和快捷方式逐字节核对。

`release-report.json` 记录每步耗时、结果和当前源码/输入指纹，日志保存在同一输出目录。失败即停止。`-Resume` 要求全部必需步骤成功，并重新校验源码、输入、测试证据和发布文件，不能把旧报告当成新代码的验证结果。

输出目录由 `.release-owner.json` 标记归属。重新构建时仅清理明确列出的测试/暂存子目录；先验证绝对路径、归属和链接，再用原生 PowerShell 删除。不会清理正式游戏数据、历史存档备份或用户偏好。

`release.json` 是发布参数及配套输入的唯一声明。Flash 和冻结宿主按验证过的二进制输入复用；修改游戏或窗口补丁源码时，必须先构建新二进制并更新对应声明。流程会拒绝“改了补丁源码却仍发布旧游戏”的组合。原有补丁构建脚本保留其调查和复现作用，日常发布从本入口进入。
