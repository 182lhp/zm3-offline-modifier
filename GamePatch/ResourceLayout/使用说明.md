
## 资源版本与文件布局（2.33.0）

「高级工具 → 资源版本」显示当前发布版本和版本指纹，可离线校验程序、游戏和图标资源。校验只读，不修改存档、设置或领取记录；发现差异后先核对自己的改动，不会自动覆盖文件。原有游戏清单仍保留。

游戏缓存按资源版本隔离，更新后使用新缓存。存档 SharedObjects 和运行配置不随缓存切换。旧缓存暂时保留，避免影响尚未关闭的游戏；缓存不是存档，不能通过删除存档来解决缓存问题。

礼包定义、自设兑换码、领取记录合并保存在 `saves/gifts/local_gifts.json`，迁移保持文件原始字节不变；只读礼包目录在 `schema/local_gift_catalog.json`。不要用旧 JSON 覆盖新文件，否则会回滚自己的配置或领取记录。`tools` 保留后台程序与内部通信文件。事务锁和待恢复日志仍在原 tools 路径，旧版中断事务可继续恢复。布局标记在 `schema/layout.json`；版本指纹及只读资源清单在 `schema/resource_manifest.json`，均不包含存档和设置。

启动游戏、启动修改器的名称、路径和快捷方式保持不变。修改器目录仍仅保留最新版的固定三个文件。源码包移除了与安装目录完全相同的 132 张礼包图片；需要重建游戏界面补丁时，先执行 `python 恢复资源.py --game-root "游戏主目录"`，按随包 SHA256 清单还原原始无损资源。C# 修改器本身的嵌入图标仍完整保留，可直接构建。还原工具会先校验全部输入，遇到不匹配版本或已有不同文件会停止，保护已有文件。

源码在仅安装 .NET 8 SDK 的离线环境中可用：先 `dotnet restore -r win-x64 -p:SelfContained=false -p:PublishSingleFile=false -p:EnableRuntimePackDownload=false`，再 `dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true --no-restore`。不需要下载自包含运行时或 ILLink 包。

技术约定：resource_manifest format=1，每项为 path、size、sha256；buildId 为 version 和按路径排序的「path TAB size TAB sha256」逐行 UTF-8 的 SHA256。排除所有用户数据、设置、日志、ref_from_game.xml、源码 ZIP 和预览，避免循环指纹。新版 root launcher 仅修改 Popen 适配器，保留宽高比、画质、窗口助手和其他启动逻辑。顶层 URL 带 zm3v、zm3h；缓存目录为 rundata/cache/buildId。HTTP 未版本化资源强制重新验证，匹配版本及实际内容摘要才标记 immutable，显式过期版本返回409。API仍不缓存。

文件迁移先在同一 tools/local_gifts.lock 下检查无未完成事务，复制原始文件并验字节，最后发布 layoutVersion=2。新旧数据不同且尚未完成迁移时禁止猜测；完成后仅使用 canonical 文件，缺失时停止，禁止静默创建空领取历史。新旧事务描述路径均解析到 canonical 文件，重复别名参与同一事务会拒绝。正式安装健康检查通过后移除两份旧数据文件。历史备份不移动。
