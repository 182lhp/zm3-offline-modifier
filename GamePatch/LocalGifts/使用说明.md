# 本地礼包兑换维护

## 离线礼包兑换

1. 在修改器打开「设置 → 本地兑换码 → 管理兑换码」，点击「新建」。
2. 填写礼包名称和兑换码；兑换码为 4–64 位字母、数字、横线或下划线，不区分大小写。
3. 选择原版礼包预设，点击「载入并替换奖励」；也可添加物品、宠物、灵魂和点券。奖励表中的数量可直接双击修改。更换预设会替换当前奖励列表，保存前请核对。
4. 设置每存档一次、每天一次或指定次数；总次数为 0 表示不限。可选择发给当前存档所有已创建角色，或仅角色 1／2。到期日期留空表示永久有效，填写日期时包含该日全天。
5. 点击「保存兑换码」。回游戏打开天庭地图底部「活动 → 礼包兑换」，输入刚设置的码，验证并预览，再点击「确认领取」。领取成功后自动保存并更新当前游戏数据，无需另外读档。

预设包含积分神秘礼包、手机客户端礼包、年兽礼包、中秋礼包、游戏盒签到礼包，奖励来自本包已有记录。预设宠物采用原版 1 级随机资质，新增后休息；原版限时时装从领取日开始计时。自定义宠物使用新增宠物窗口选择的形态和生成方式。首次安装不会自动创建兑换码或发放礼包。

物品、宠物和灵魂分别发给目标角色；点券属于账号共享余额，每次兑换只增加一次，不计入累计充值，也不改变 VIP 等级。背包满、宠物栏满、堆叠超限或存档冲突时整次取消，不消耗领取次数。验证后未确认、取消窗口均不发奖。奖励过多时，可在游戏奖励预览区滚动查看。

每天次数按北京时间自然日计算，依赖本机时间。已领取记录可在管理窗口的「领取记录」中刷新查看。修改器保存配置会保留最新领取记录；更改奖励、次数或启停状态后，游戏重新验证即可使用，无需重启。

这些是自己设置的本地礼包，不验证官方平台兑换码，也不连接 4399 的兑换服务。旧推广页面继续隐藏，八个本地挑战入口保持原有规则。

兑换配置和领取记录一起保存在 `tools/local_gifts.json`。恢复旧的角色存档不会清空已领取记录。更新时保留这个文件；做完整备份时同时备份它。不要手工删除记录来修复一次未确认的兑换：连接中断时点击「确认领取」重试同一次请求，系统会核对结果并避免重复发放。

如果出现 `tools/local_gifts.transaction.json`，表示有待完成的写入事务。请正常启动游戏，让本地后台自动恢复，再打开兑换码管理。原存档备份保存在 `saves/backups/redeem-slot…json`。不要在恢复期间手动改这些文件。

后台使用 Python 3.8，通过原本地服务的 Handler 加入两个兑换端点，不改变原接口。配置由 WPF 写入，双方锁定同一个字节；发奖使用当前游戏序列化快照，先记录可重放事务，再更新存档与领取记录。`/local-gifts/status` 可核对模块版本与目录。

仅重新编译 `export.SelectPLace`，原有奖励类和战斗、地图类保持不变。旧平台的核验服务器无法由本包离线恢复，这里复用已核对的奖励内容和现有数据工厂，提供可配置的本地兑换流程。未穷举移植所有历史活动的各档奖励。
