# 统一规则数据

唯一编辑入口是 `definitions.json` 和 `Inputs` 中经过 SHA256 固定的原版提取资料。`definitions.json` 记录规则版本、配套游戏哈希、每份输入的哈希和来源说明。原版引用条目保持原值；缺少的十二种精灵只依据明确的 PetEquipObj 构造参数在构建时补齐，不能使用其他装备最大值推测。

`Build/generate_rules.py` 确定性生成以下三项：

- `Rules/generated.json`：同一份数据同时作为部署的 `schema/game_rules.json` 和修改器内嵌资源。
- `GameRules.Generated.cs`：修改器期待的规则摘要。
- `Build/runtime/rules_stamp.py`：礼包后台期待的同一个摘要。

生成文件不手工编辑。使用 `python Build/generate_rules.py --check` 检查生成物是否过期，或运行根目录 `release.ps1` 完成生成和全部验证。修改提取输入须显式更新来源哈希；改变配套游戏时还须更新游戏输入声明。仅复制另一版本的 JSON 会被 C# 和 Python 同时拒绝。

运行时的装备引用、强化系数、宠物品种/形态/技能条件、技能说明、角色参考、VIP、药园、土地庙、增益与容量数据均从生成库读取。算法及存档序列化结构仍由代码实现；本次提取保持既有数值和行为。旧 schema 在游戏目录保留兼容，修改器与礼包后台不再分别混用它们来拼接规则。

旧安装没有统一规则文件时，修改器可以读取同一份内嵌生成物；有外部文件时必须与程序摘要一致。后台始终使用本次安装的配套规则文件，不创建空领取历史或改写用户存档来处理规则错误。
